# 노션 데이터 챗봇 검색 연동

## 2026-08-10 | 요구사항 확정 + 스크립트/챗봇 연동 구현

### 요청
- "노션 API를 이용해서 chat 에서 검색할 데이터를 추가하고 싶어"
- 4라운드 확인 결과: 노션 상위 페이지 1개+하위 페이지 전체 → 기존
  `dho_structured.sqlite3`에 새 테이블로 저장 → Python 스크립트로 매일 1회 동기화
  → 챗봇이 검색.
- 대상 페이지: https://app.notion.com/p/deitrihi-screte/9f16031c9d82446cb9f851eb4b235be8
  (페이지 ID `9f16031c9d82446cb9f851eb4b235be8`). Integration 토큰은 이미 발급되어
  `.env`의 `NOTION_API_KEY`에 저장돼 있었음.

### 행동
- 이전 FTS5 검색 효율화 작업의 `plan.md`/`checklist.md`/`context-notes.md`를
  `*-search-fts5.md`로 보존하고, 이번 작업용으로 새로 작성.
- `sync_notion.py` 신규 작성 — Notion REST API를 `requests`로 직접 호출(notion-client
  패키지 추가 안 함, `scraper.py`와 동일한 방식). 상위 페이지부터 `child_page` 블록을
  재귀 추적해서 하위 페이지 전체를 수집, 블록의 rich_text를 plain text로 이어붙여
  `content`에 저장. 실행마다 `notion_pages`/`notion_fts`(FTS5, trigram) 전체 재적재.
- `chat/lib/dho-db.ts`에 `searchNotion()` 추가 — 기존 `findMatchingItems()`(items_fts)와
  동일하게 bm25 정렬 + 3글자 미만 키워드 LIKE 폴백. `notion_fts` 테이블이 아직 없으면
  (동기화 전) 에러 메시지 반환하도록 방어.
- `chat/app/api/chat/route.ts`에 `search_notion` 도구 등록, SYSTEM_PROMPT에 사용 시점
  안내 추가.
- `.env.example`에 `NOTION_API_KEY` 항목, `README.md`에 "노션 문서 동기화" 절 추가.
- `npx tsc --noEmit`으로 chat 타입체크 통과 확인.
- `python sync_notion.py <URL>` 실제 실행 — 첫 시도는 출력을 파이썬 subprocess로
  캡처하는 wrapper로 감싸서 실행했더니 완료 전까지 진행상황이 전혀 안 보여 24분 만에
  중단 판단 후 kill, `python -u`로 직접 실행 + 로그 파일 스트리밍하는 방식으로 재실행.

### 결정
- 게임 위키 데이터(`items_fts`)와 성격이 다른 데이터라 같은 DB 파일 안에서도 테이블/FTS
  인덱스는 분리(`notion_pages`/`notion_fts`).
- `openwebui_tool_dho_sql.py`(레거시, `chat/`으로 대체됨)는 손대지 않음.
- `dho_structured.sqlite3`/`.env` 둘 다 `.gitignore` 대상이라 노션 개인 문서가 git에
  올라갈 위험 없음 — 별도 마스킹 처리 안 함.

### 결과 (같은 세션, 후속)
- 로컬 동기화 완료 — 50개 페이지 적재, `notion_fts` MATCH 검색 정상 동작 확인
  (Git Bash 콘솔에 출력된 mojibake는 콘솔 코드페이지 표시 문제였을 뿐 DB 데이터는
  정상 UTF-8이었음 — 파일 덤프 후 Read 툴로 재확인).
- 사용자가 "NAS에 배포된 DB가 있고 webapp이 거기 직접 쓰고 있다"고 알려줘서 배포 전략
  재설계 — `deploy.sh`가 이미 `dho_structured.sqlite3`를 배포 제외 중(NAS가 최신)이라는
  기존 관례를 확인하고, 사용자에게 "NAS가 주 사용처"라는 답을 받은 뒤 방향을
  Windows 작업 스케줄러 → NAS docker-compose 컨테이너 서비스로 전환.
- `Dockerfile.notion-sync` + `sync_notion_loop.sh`(컨테이너 내부 `sleep 86400` 루프) +
  `docker-compose.yml`의 `notion-sync` 서비스(webapp과 동일하게 DB 읽기-쓰기 마운트) 신규
  작성. `deploy.sh`에 `notion-sync` 서비스 인자 추가, `.env`/`.env.example`에
  `NOTION_ROOT_PAGE` 추가.
- 부수 발견(미수정, 사용자에게만 알림): webapp용 `Dockerfile`이 `build_search_index.py`를
  이미지에 안 담고 있어 NAS에서 항목 저장 시마다 파생 테이블 재생성 파이프라인 중
  FTS5 인덱스 재빌드 단계가 실패하고 있을 가능성.
- `docker compose config`(YAML 유효성), `bash -n`(셸 문법) 검증 완료. 로컬 Docker 데몬이
  꺼져 있어 실제 이미지 빌드는 검증 못 함 — NAS 배포 시 확인 필요.

### 미해결
- 사용자가 `./deploy.sh` 또는 `./deploy.sh notion-sync`를 실행해서 NAS에 실제 반영해야
  함 (SSH 접근 권한이 없어 이 부분은 직접 실행 불가).
- NAS 배포 후 챗봇에서 `search_notion` 실제 질의 동작 확인 필요.
- 커밋은 아직 안 함.
