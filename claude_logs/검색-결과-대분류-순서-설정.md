# 검색 결과 대분류 순서 설정 페이지

## 요청
- "검색 결과에 따른 카테고리의 순서를 변경하고 싶은데, 어떻게 하는게 좋을까?" → 세
  가지 정렬 기준 옵션을 제시했으나 사용자가 "webapp에 설정 페이지를 만들고, 검색
  결과의 대분류 순서를 정하는 메뉴를 넣어줘"로 방향 전환.

## 행동
- `dho_webapp.py`: 새 테이블 `search_group_order(group_title, sort_order)` —
  사용자 커스텀 순서만 저장, 값 없으면 `category_localization`의 기본 대분류
  순서(사이드바와 동일)로 폴백. 모듈 로드 시 `CREATE TABLE IF NOT EXISTS`로 스키마
  보장, 크롤링 파이프라인(`DERIVED_PIPELINE_SCRIPTS`)과는 분리.
- `get_search_group_order()` 헬퍼, `/settings`(GET) + `/settings/move-group`(POST,
  ▲▼로 순서 스왑) 라우트 추가.
- `get_search_results()`를 그룹 순서(설정값) → 그룹 내 매칭 건수 내림차순으로
  정렬하도록 변경.
- `templates/settings.html` 신규(list-group-numbered + 순수 폼 버튼, JS 없음),
  `base.html` 상단바에 설정(⚙) 링크 추가.
- 검증: 기본 순서 확인 → "세계" 그룹을 맨 위로 이동 → 검색 결과에서 실제로 순서가
  바뀌는 것 확인. 145개 라우트 스모크 테스트 통과. Playwright로 버튼 클릭 동작
  확인. `./deploy.sh webapp`로 NAS 배포, 배포 후 `/settings` 응답 확인.

## 결정
- `category_localization`(원본 사이트에서 옮겨온 사실 데이터)을 직접 편집하지 않고
  별도 오버레이 테이블로 분리 — 재크롤링/데이터 갱신에도 사용자 설정이 안전.
- 그룹 내부 정렬 기준(매칭 건수 내림차순)은 별도 확인 없이 이전 대화에서 보여준
  옵션 중 합리적인 걸 기본값으로 채택.

- 없음.

## 추가 요청 (같은 세션) — 대분류 하위 소분류 순서

### 요청
- "대분류 하위에 소분류도 설정할 수 있으면 좋겠어."

### 행동
- 새 테이블 `search_category_order`(대분류 오버레이와 동일 패턴). 대분류 하나라도
  소분류 순서를 커스터마이징하면 그 대분류는 "커스텀" 상태로 전환되어 저장된 순서를
  전적으로 따르고, 손 안 댄 대분류는 기존처럼 매칭 건수 내림차순 유지 — 부분 커스텀은
  안 함(대분류 단위 on/off 모델).
- `get_effective_category_order()`/`get_customized_search_groups()` 헬퍼,
  `/settings/move-category` 라우트 추가. `settings.html`을 대분류 아코디언 안에
  소분류 번호 목록 + ▲▼가 있는 구조로 재작성, 커스터마이징된 대분류엔 뱃지 표시.
- 검증: "아이템" 그룹 마지막 소분류를 맨 위로 이동 → 검색 결과 전체 순서에서 정확히
  "모험" 그룹 블록 끝(인덱스 14) 위치로 이동, 손 안 댄 "모험" 그룹은 그대로임을 확인.
  145개 라우트 재통과 후 NAS 배포.

### 결정
- 부분 커스텀(일부 소분류만 순서 지정, 나머지는 건수순 섞임) 대신 대분류 단위
  on/off — 사용자가 예측하기 쉬운 단순한 모델 우선, 별도 확인 없이 판단.

### 미해결
- 없음.
