# 챗봇 응답 마크다운/구조화 렌더링

## 요청
- "chat 의 응답이 text로만 나오는데, 응답 내용에 따라서 다르게 보여주고 싶어"

## 조사
- `chat/`는 OpenWebUI를 대체하는 Vercel AI SDK(Next.js) 기반 Text-to-SQL 챗봇 프론트엔드.
  `dho_webapp.py`의 `/assistant` 페이지는 이 서비스를 iframe으로 감싸기만 함
  ([templates/chat.html](../templates/chat.html)).
- `chat/app/page.tsx`가 assistant 텍스트 파트를 `<span>{part.text}</span>`로만 렌더링,
  tool 결과도 `JSON.stringify(input)` 한 줄로만 표시하고 있었음.
- 반면 `chat/app/api/chat/route.ts`의 시스템 프롬프트는 "표/목록을 활용해서 간결하게
  정리해서 답하세요"라고 지시 — 즉 모델이 마크다운 표를 생성해도 화면엔 `| 이름 | 값 |`
  같은 raw 텍스트로만 보이는 불일치가 원인이었음.

## 사용자 확인
- 범위를 "마크다운 렌더링만" vs "마크다운 + 도구 결과 구조화" 중 선택받음 → 후자 선택.

## 행동
- `chat/`에 `react-markdown@10.1.0`, `remark-gfm@4.0.1`, `remark-breaks@4.0.0` 설치.
- `chat/app/components/rich-content.tsx` 신규 작성.
  - `MarkdownText`: 표/목록/코드블록/볼드/링크 등 다크 테마에 맞춘 커스텀 컴포넌트로 렌더링.
    `remark-breaks`를 같이 써서 마크다운 문법을 안 쓴 일반 텍스트도 기존처럼 단일
    줄바꿈이 그대로 보이게 유지(회귀 방지).
  - `JsonValue`(+`JsonTable`): tool 실행 결과 JSON을 재귀적으로 순회 — 배열-of-객체는
    표, 객체는 key-value 목록, 그 외엔 텍스트로 렌더링. 6개 도구(list_categories/
    get_item_detail/search_items/find_tables/get_table_schema/run_sql) 결과 형태를
    전부 하나의 범용 컴포넌트로 커버(도구별 전용 카드 대신 단순화).
- `chat/app/page.tsx`: 텍스트 파트를 `MarkdownText`로, tool 파트를 `<details>`(스트리밍
  중엔 접힘, 완료 시 자동 펼침) + `JsonValue`로 교체. 메시지 버블의 `whitespace-pre-wrap`은
  마크다운이 자체적으로 줄바꿈을 처리하므로 제거.

## 검증
- `npm run build` — 컴파일/타입체크 통과.
- `npm run lint` — 통과.
- `npm run dev`로 로컬 기동 후 `curl localhost:3001/` 200 확인(페이지 렌더링만 확인,
  이 환경엔 OPENAI_API_KEY가 없어 실제 LLM 스트리밍 응답까지는 미검증).

## 미해결
- 실제 OpenAI 호환 API 키가 있는 환경에서 브라우저로 표/목록 응답이 실제로 잘 그려지는지
  최종 육안 확인은 아직 안 함 (다음에 배포/로컬 `.env.local` 설정된 환경에서 확인 필요).

## 추가: 도구 호출 한도(stepCountIs)로 응답이 멈추는 버그 (같은 세션, 실사용 중 발견)

### 증상
- 사용자가 "포술을 얻을 수 있는 NPC에 대해서 위치와 이름을 정리해줘"라고 질문 → 도구
  호출(get_item_detail/list_categories/find_tables/get_table_schema×4/run_sql) 8개가
  전부 `output-available`로 끝난 뒤 최종 답변 텍스트 없이 그대로 멈춤. 스크린샷으로 확인.

### 원인
- `chat/app/api/chat/route.ts`의 `stopWhen: stepCountIs(8)` — 도구 탐색(get_table_schema를
  여러 하위 테이블에 대해 반복 호출)만으로 8스텝을 전부 소진해서, 모델이 최종 종합 답변을
  생성할 스텝이 남지 않은 채 스트림이 종료됨. AI SDK는 stopWhen 조건 충족 시 그 스텝에서
  즉시 루프를 끊기 때문에, "텍스트 없이 끝난 assistant 턴"이 되어도 별도 에러가 나지 않아
  프론트에는 아무 표시가 없었음(이번 렌더링 작업 전엔 tool 파트도 안 보여서 더 눈치채기
  어려웠을 것).

### 수정
- `stopWhen: stepCountIs(8)` → `stepCountIs(16)`로 상향.
- `chat/app/page.tsx`: 마지막 메시지가 assistant이고 텍스트 파트가 하나도 없는 채로
  스트리밍이 끝나면(`!busy`) 노란색 경고 문구("도구 호출 한도에 도달해 답변을 끝맺지
  못했습니다...")를 표시하도록 fallback 추가 — 이후에도 한도에 걸리면 최소한 사용자가
  "멈춘 게 아니라 실패했다"는 걸 알 수 있게 함.

### 검증
- `npm run build`/`npm run lint` 통과. 실제 LLM로 재현/재검증은 API 키 미설정 환경이라
  못함 — 사용자가 같은 질문으로 재시도해서 확인 필요.

## 추가: 도구 결과 자동 펼침 제거 (같은 세션, 실사용 스크린샷 기반 피드백)

### 요청
- "검색을 하면 쿼리 결과가 표로 나오고 있는데, 쿼리 결과까지는 펼쳐서 보여줄 필요 없고
  응답 내용만 표 같은 것으로 정리해서 보여주면 되" — get_item_detail 등 tool 결과가
  `output-available` 시 자동으로 펼쳐지면서 화면을 다 차지하는 스크린샷 첨부.

### 원인
- 직전 작업에서 `<details open={finished}>`로 만들어 tool 호출이 끝나면 자동으로 펼쳐지게
  했었는데, 이게 사용자가 원하는 동작이 아니었음 — 최종 답변(이미 `MarkdownText`로 표/목록
  포맷팅되어 잘 나오고 있었음)만 보면 되고, 중간 쿼리 결과는 접혀 있어도 됨.

### 수정
- `chat/app/page.tsx`: `<details>`의 `open={finished}` 제거 — 기본 접힘, 필요하면
  `<summary>` 클릭으로 직접 펼쳐볼 수 있게만 유지.

### 검증
- `npm run build`/`npm run lint` 통과.
