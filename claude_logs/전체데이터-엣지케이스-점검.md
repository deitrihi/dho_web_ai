# 전체 데이터 엣지케이스 점검 및 수정

## 요청
- "우선 나머지 전체 데이터에 대해서 구현해줘" — NEXT_STEPS.md에 있던
  "소규모 샘플(cannon 등) 확인 끝났으니 전체 70개 카테고리로 스타일/엣지케이스 확장
  검토" 항목을 실제로 진행

## 방법
- 33,496건 전체를 다 눈으로 볼 수는 없어서 두 갈래로 접근.
  1. **자동화**: Flask `test_client()`로 전체 33,496건 상세 페이지 + 70개 카테고리
     목록 페이지 + 홈을 순회하며 500 에러 여부만 기계적으로 체크 (in-process라 33k건도
     6~7분이면 끝남)
  2. **극단값 샘플링**: `dho_structured.sqlite3`에서 라벨 길이 최댓값, 표 헤더 개수
     최댓값, 이미지 개수 최댓값 등을 SQL로 직접 뽑아서 그 항목들만 골라 Playwright로
     스크린샷 검증 — "평균적인" 샘플이 아니라 레이아웃이 깨질 가능성이 가장 높은 항목을
     타겟팅

## 발견 및 수정
1. **CJK 줄바꿈 버그**: `shipDecor`의 "장비 부분 선측 후방 오른쪽"(15자) 라벨이 120px
   고정폭 컬럼에서 "오른쪽"이 "오"+"른쪽"으로 음절 중간에 끊겨 나옴. `body`에
   `word-break: keep-all` 추가로 해결. (`overflow-wrap: break-word`도 같이 넣었다가
   표 셀의 auto layout이 "소비품"처럼 짧은 내용까지 과도하게 좁혀서 줄바꿈시키는 부작용을
   발견해서 뺐음 — keep-all 단독으로 두 케이스 다 해결됨)
2. **중첩 테이블 버그**: `raw_tables`에서 헤더-셀 개수 불일치 2,721건 발견. 원인 추적
   결과 discovery의 "논전 콤보"/"장식품", quest의 "필요"(총 1,345건 영향)가 한 셀 안에
   여러 항목을 나열할 때 `<table>` 안에 또 `<table>`을 중첩하는 구조를 씀. 기존
   `table.find_all("tr")`/`tr.find_all("td")`가 기본적으로 재귀 탐색이라 중첩 표의
   행/셀까지 바깥 표 것처럼 섞여 들어갔음(예: "논전 콤보" 표가 헤더 3개인데 셀 6개를
   주워서 카운트 불일치 + 중첩 표의 tr이 바깥 표의 유령 행으로 중복 추가됨).
   `tbody.find_all("tr", recursive=False)` / `tr.find_all("td", recursive=False)`로
   직계 자식만 스코프 제한해서 중첩 표를 안 건드리게 하고, `parse_cell()`에 중첩 표
   전용 처리를 추가 — 중첩 표의 각 셀을 ", "로 이어붙인 인라인 텍스트로 펼침(원본
   소스가 셀 사이 공백 없이 붙어있어서 그냥 get_text()하면 "카르타고 유적한니발대리석상
   스키피오전의 태피…"처럼 다 붙어버림). 링크는 그대로 유지되어 클릭 가능. 수정 후
   불일치 0건 확인
3. **row-value 개행 손실 + Jinja 공백 재발**: "연결 지도/퀘스트"처럼 원본이 의도한
   개행이 있는 속성값이 개행 없이 붙어 보이던 문제 발견(원본 소스에 실제 `\n`이 있는데
   `.row-value`에 `white-space: pre-wrap`이 없어서 브라우저가 공백으로 뭉갬).
   `pre-wrap`을 추가했더니 예전에 `.links`에서 겪었던 것과 정확히 같은 계열의 버그가
   재발 — Jinja `{% if %}`/`{% for %}` 블록 사이 들여쓰기 공백이 그대로 노출되어 모든
   속성 행마다 큰 빈 줄이 생김. 이번엔 CSS로 또 땜빵하는 대신 `dho_webapp.py`에
   `app.jinja_env.trim_blocks = True` / `lstrip_blocks = True`를 설정해서 템플릿
   블록 태그 주변 공백이 애초에 렌더링 결과에 안 남도록 근본 원인을 고침

## 배운 것
- Playwright의 `full_page=True` 스크린샷은 `document.body.scrollHeight` 기준으로
  캡처 범위를 잡는데, 우리 셸 레이아웃(`main`이 자체 `overflow-y:auto`를 가지는 구조,
  원본 사이트와 동일한 패턴)에서는 body가 아니라 `main`이 스크롤 컨테이너라 body의
  scrollHeight가 viewport 높이에 고정됨 → full_page 스크린샷이 뷰포트 밖 콘텐츠를
  누락시킴. `main.scrollHeight`를 직접 읽어서 뷰포트 높이를 그만큼 늘린 뒤 캡처하는
  방식으로 우회. 이전 세션들의 스크린샷 검증도 우연히 콘텐츠가 짧아서 문제가 안
  드러났을 뿐, 앞으로 긴 페이지 검증할 땐 이 방식을 써야 함
- CSS `white-space: pre-wrap`을 새 요소에 추가할 때마다 Jinja 템플릿의 공백이 새어
  나오는 문제가 반복됐음(이번이 세 번째: 표 셀 텍스트 → `.links` → `.row-value`).
  근본 원인(템플릿 자체의 공백)을 안 고치고 매번 CSS로 개별 요소를 막다 보면 같은
  패턴이 계속 재발할 것 같아서, 이번엔 `trim_blocks`/`lstrip_blocks`로 소스를 고쳤음
