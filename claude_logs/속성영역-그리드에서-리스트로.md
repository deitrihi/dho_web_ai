# 상세 페이지 속성 영역: 그리드 → 리스트 레이아웃 변경

## 요청
- 직전 세션에서 만든 상세 페이지 속성 그리드(2단 배치)가 원본과 다름 — 사용자가 원본
  사이트에서 quest/15390("피에 굶주린 폭군") 스크린샷을 캡처해서 제공, 라벨-값이 한 줄씩
  쌓이는 리스트 형태로 바꿔달라는 요청

## 행동
- `templates/item.html`: attrs와 tables를 각각 따로 렌더링하던 걸 `.row-list` 하나로
  통합, 둘 다 동일한 `.row`(라벨+값) 구조 사용하도록 재작성 (`dt`/`dd` 시맨틱 태그 대신
  범용 `.row-label`/`.row-value` div로 통일 — 표 행도 같은 라벨 폭에 맞춰야 해서)
- `static/style.css`: `.attr-grid`(CSS grid 다단 배치)와 `.table-block`(표 전용 별도
  블록) 클래스를 `.row-list`/`.row`/`.row-label`(120px 고정폭)/`.row-value`로 교체
- Playwright로 equipment/6582, quest/15390 두 페이지 스크린샷 찍어서 원본과 대조 검증

## 발견 (이번엔 안 고침, NEXT_STEPS.md에 기록)
- quest/15390을 원본과 나란히 비교하다가 레이아웃과 무관한 두 가지 이슈 발견.
  1. **순서 불일치**: 우리는 attrs 전부 → tables 전부 순으로 렌더링하는데, 원본은 문서
     순서대로 attrs/tables가 섞여서 나옴 (원본은 "필요"/"보상" 표가 "분류"/"난이도"
     바로 다음인데, 우리는 맨 아래). `extract_detail()`이 파싱 시점에 attrs/tables를
     별도 리스트로 나누면서 상대 순서를 버려서 생긴 문제 — 고치려면 raw_attrs/
     raw_tables에 순서 컬럼 추가 + 전체 재스테이징 필요, 이번 요청 범위 밖이라 보류
  2. **데이터 버그**: `raw_attrs`에서 quest/15390의 "이미지" 속성 값이 `"공략"`으로
     잘못 들어있음 (원본은 실제 이미지가 그 자리에 표시됨). "이미지" 행의 DOM 구조가
     보통 라벨+값 div 쌍과 다른 것으로 추정 — `extract_detail()`의 라벨/값 매칭 로직이
     이 케이스에서 어긋나는 듯. 원인 조사 안 함, 다음 세션 후보

## 결정
- 두 발견 사항은 레이아웃 변경 요청과 무관한 별도 버그라서 고치지 않고 NEXT_STEPS.md에
  기록만 하고 사용자에게 보고 — 순서 문제는 스키마 변경+전체 재스테이징이 필요한 큰
  작업, 이미지 버그는 원인 조사부터 필요해서 범위 판단을 사용자에게 맡김

## 미해결
- 위 순서 불일치, 이미지 속성 데이터 버그
- 카테고리 목록 통계 컬럼 표, 백링크 섹션 (이전 세션부터 이어지는 미해결 항목)
