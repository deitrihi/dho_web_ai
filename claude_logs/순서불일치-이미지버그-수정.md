# 순서 불일치 + 이미지 속성 데이터 버그 수정

## 요청
- 직전 세션에서 리스트 레이아웃 검증 중 발견하고 NEXT_STEPS.md에만 기록해뒀던 두 이슈
  ("이어서 수정해줘" 요청) — quest/15390 대조 중 나온 순서 불일치, "이미지" 속성 데이터 버그

## 조사
- 순서 문제: `build_structured_db.py`의 `extract_detail()`이 `main.select("div.flex.gap-4")`
  를 한 번에 순회하지만 attrs/tables를 별도 리스트에 나눠 담아서, DB에 적재된 이후에는
  둘 사이의 원래 상대 순서 정보가 완전히 사라져 있었음. 원본 캐시 HTML로 quest/15390의
  실제 행 순서를 직접 확인: 분류→난이도→필요(표)→보상(표)→목적지→...→이미지 순
- 이미지 버그: raw_attrs에서 "이미지" 속성의 텍스트가 `"공략"`으로 잘못 들어있던 원인을
  캐시된 원본 HTML에서 직접 확인. "이미지" 행의 값 div가
  `<figure><img alt="공략" src="..."><figcaption>공략</figcaption></figure>` 구조였는데,
  `parse_cell()`의 `td.get_text()`가 이 안의 유일한 텍스트 노드인 figcaption("공략")을
  주워버린 것. 라벨/값 매칭 로직 자체는 문제 없었음 — 순수하게 이미지 캡션이 텍스트
  추출기에 섞여 들어간 문제
- 이미지가 테이블 셀 안에도 나오는지 400개 페이지 랜덤 샘플로 조사 — attr 레벨("이미지"
  라벨)에서만 24건 발견, 표 셀 안에서는 0건. 이미지 처리는 attr 레벨만 대응하면 충분함을
  확인
- 이미지 src가 모두 절대 URL(supabase storage 공개 버킷)인지 샘플로 확인 — 전부 절대
  URL이라 그대로 참조(핫링크) 가능

## 행동
- `build_structured_db.py`
  - SCHEMA_VERSION 2 -> 3, `raw_attrs`에 `images_json`/`position`, `raw_tables`에
    `position` 컬럼 추가. 기존 마이그레이션 감지 로직(컬럼 존재 여부로 DROP+재생성)에
    `raw_attrs.position` 체크 추가
  - `parse_cell()`: `<figure>`(및 벌거벗은 `<img>`)를 먼저 찾아서 `{src, alt, caption}`
    리스트로 뽑아내고 `decompose()`로 트리에서 제거한 뒤 나머지 텍스트를 추출하도록 변경
    (이러면 `get_text()`가 더 이상 캡션 텍스트를 못 주움)
  - `extract_detail()`: `main.select(...)` 순회 중 순번(`position`)을 매겨서 attrs/tables
    양쪽 항목에 저장
  - `stage_all()`: `images_json`/`position` 컬럼 INSERT 반영
- `dho_webapp.py`의 `item_detail()`: attrs/tables를 각각 조회한 뒤 `position` 기준으로
  하나의 `rows` 리스트로 병합·정렬해서 템플릿에 전달 (예전엔 attrs 리스트, tables 리스트
  둘을 따로 넘겨서 템플릿이 attrs 전부 -> tables 전부 순으로 렌더링할 수밖에 없었음)
- `templates/item.html`: `rows`를 순서대로 순회하며 `r.type`으로 attr/table 분기 렌더링,
  attr에 `images`가 있으면 `<figure><img loading="lazy"></figure>`로 표시
- `static/style.css`: `.row-images`/`.row-images img`/`.row-images figcaption` 스타일 추가
- 전체 재스테이징(`build_structured_db.py stage`, 스키마 마이그레이션이 라운드마다 테이블을
  DROP하기 때문에 카테고리 일부만 다시 스테이징하면 나머지 데이터가 통째로 날아감 — 처음에
  quest만 20건 테스트하다가 이걸 깨닫고 바로 전체 33,496건 재스테이징으로 이어감) +
  `build_acquisition.py` + `materialize_cannon/recipe/consumable/tarotcard/generic.py`
  전체 재실행
- Playwright로 quest/15390 스크린샷 찍어서 순서 정상화("필요"/"보상" 표가 이제 "분류"/
  "난이도" 바로 다음) + 실제 지도 이미지가 렌더링되는 것 확인. 첫 스크린샷에선 이미지가
  `loading="lazy"` + 스크롤 전이라 안 보였는데, 스크롤 + networkidle 대기 후 재확인하니
  정상 로드됨(사족: sandbox에서 실제 supabase 이미지 URL로 직접 요청해서 200 응답도 확인)

## 결정
- 이미지는 로컬로 다운로드/캐싱하지 않고 원본 supabase storage 공개 URL을 그대로 참조
  (핫링크). 원본 서비스가 내려가지 않는 한 문제없고, 33k건 전체 이미지를 다운로드하는 건
  이번 요청 범위를 크게 넘는 별도 작업이라 판단
- 표 셀 내부 이미지는 지원 안 함 (400건 샘플 조사에서 0건 확인돼서 우선순위 낮음)

- 나머지 70개 카테고리 스타일 엣지케이스 확장 검토
