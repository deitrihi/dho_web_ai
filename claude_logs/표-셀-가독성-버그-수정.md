# 표 셀 텍스트 가독성 버그 수정

## 요청
- NEXT_STEPS.md에 기록된 "표 셀 텍스트가 원본처럼 자연스럽게 안 읽힘" 이슈 확인
- 대조 대상: 로컬 http://localhost:5050/equipment/6582 vs 원본
  https://dho-archive.vercel.app/db/equipment/6582

## 조사
- `dho_cache.sqlite3`에서 equipment/6582 원본 HTML을 직접 열어 획득 방법 표 첫 td를
  BeautifulSoup으로 파싱, 실제 텍스트 노드를 `repr()`로 하나씩 확인
- 원본 텍스트 노드는 이미 필요한 공백을 포함하고 있음
  (`'모험 | '`, `' ( 4 '`, `' 1, '` 등 — 링크 앞뒤로 공백이 노드 안에 내장돼 있음)
- 버그 원인: `build_structured_db.py`의 `parse_cell()`이
  `td.get_text("\n", strip=True)`를 사용 — 이게 각 텍스트 조각을 개별적으로 strip한 뒤
  "\n"으로 이어붙이는 방식이라, 조각 경계의 의미 있는 공백이 사라지고 링크/툴팁마다
  줄바꿈이 삽입됨 (표에 `white-space: pre-wrap`이 걸려있어 그 줄바꿈이 그대로 렌더링됨)
- `<br>` 태그는 캐시 전체(`dho_cache.sqlite3`) 어디에도 없음을 확인 → 셀 내 의도된
  줄바꿈은 없고, description 필드(`desc_p.get_text("\n")`)만 실제 개행이 필요한
  단일 텍스트 노드라 그대로 둬도 문제없음

## 행동
- `build_structured_db.py`의 `parse_cell()`: `get_text("\n", strip=True)` →
  `get_text().strip()`로 교체 (구분자 없이 원본 텍스트 노드를 그대로 이어붙임)
- 파이프라인 전체 재실행: `build_structured_db.py stage`(33,496건, 0 실패) →
  `build_acquisition.py` → `materialize_cannon.py`/`materialize_recipe.py`/
  `materialize_consumable.py`/`materialize_tarotcard.py`/`materialize_generic.py`
- 로컬 웹앱(:5050) 재기동 후 equipment/6582, consumable/1016856 두 항목으로
  렌더링 결과 확인 — "모험 | 피에 굶주린 폭군 ( 4 탐색 1, 고고학 2, 이탈리아어 1) -
  마르세이유 , ?…", "연금술 11, 봉제 11" 등 자연스럽게 한 줄로 읽힘 (수정 전엔 단어마다
  줄바꿈되던 것)
- CHANGELOG.md `[미커밋]`, NEXT_STEPS.md 알려진 이슈 항목 갱신

## 결정
- raw_attrs/raw_tables만 고치는 게 아니라 `build_acquisition.py`/`materialize_*.py`까지
  전체 재실행함 — 이 스크립트들도 같은 raw_attrs/raw_tables를 소스로 쓰기 때문에
  안 고치면 LLM 검색용 테이블(`item_acquisition_*`, 카테고리별 전용 테이블)에는 여전히
  깨진 텍스트가 남게 됨
