# 원본 사이트 레이아웃 기반 디자인 리뉴얼

## 요청
- 웹앱 전체 디자인이 안 예뻐서 원본 사이트(dho-archive.vercel.app)와 같은 레이아웃을
  갖되, 색상은 지금 쓰고 있는 다크 테마를 그대로 유지해달라는 요청
- 사용자가 원본 레이아웃 스크린샷을 캡처해주겠다고 제안함

## 조사
- 스크린샷 없이도 `dho_cache.sqlite3`에 캐싱된 원본 페이지 HTML(전체 body, `<main>` 밖의
  헤더/사이드바 포함)을 직접 파싱해서 Tailwind 클래스 구조를 확인 — 스크린샷보다 오히려
  정확한 레이아웃 소스
- 구조 파악 결과.
  - 좌측 사이드바(220px 고정, 로고 + 대분류 6개 접이식 내비게이션)
  - 상단 헤더바(사이트명 + 검색창) + 브레드크럼 바(홈 아이콘 › 대분류 › 카테고리 › 항목명)
  - 상세 페이지: 카드형 섹션(rounded border), 제목+카테고리뱃지 헤더, 설명 박스, 속성
    2단 그리드, 표는 라운드보더+헤더행 음영, 하단에 "이 항목을 참조하는 곳" 백링크 섹션
  - 카테고리 목록 페이지: 예상과 다르게 단순 목록이 아니라 카테고리별로 다른 통계
    컬럼(예: 장비품은 분류/내구/공격/방어/복장/변장/사용효과/스킬/장비효과)을 가진
    정렬 가능한 데이터 테이블 + 필터 패널이었음. 이건 카테고리 70개마다 어떤 속성을
    컬럼으로 보여줄지 스키마 판단이 필요한 큰 별도 작업이라 사용자에게 범위를 확인함

## 결정
- 사용자가 "단순 목록 우선 진행" 선택 → 카테고리 목록 페이지의 통계 컬럼 테이블/정렬/필터
  기능은 이번 범위에서 제외, 카드 스타일 컨테이너로만 재구성
- 백링크("이 항목을 참조하는 곳") 섹션도 이번엔 구현 안 함 — 로컬 DB에 역방향 링크
  인덱스가 없어서 전체 33k건을 스캔해야 하는 별도 작업이라 순수 레이아웃 변경 범위를 넘어감
- 색상 팔레트(CSS 변수 --bg/--fg/--muted/--border/--accent/--row-alt)는 전혀 안 건드리고,
  카드/사이드바/헤더/표 헤더용 변수만 추가해서 라이트/다크 둘 다 자연스럽게 어울리도록 함

## 행동
- `dho_webapp.py`: `get_nav_groups()`/`get_group_title()` 추가, `context_processor`로
  모든 페이지에 사이드바 내비게이션 데이터 주입. `item_detail()`에 `category` 변수를
  템플릿에 안 넘기고 있던 기존 버그도 발견해서 수정(사이드바 활성 카테고리 하이라이트가
  상세 페이지에서 동작 안 하고 있었음)
- `templates/base.html`: 사이드바+헤더바+브레드크럼 셸 구조로 재작성
- `templates/item.html`: 카드 섹션 + 2단 속성 그리드 + 라운드보더 표
- `templates/category.html`: 카드 스타일 컨테이너 (단순 목록 유지)
- `templates/index.html`: 대분류 그룹을 카드 스타일로
- `static/style.css`: 전면 재작성
- Playwright로 라이트/다크 스크린샷을 찍어서 직접 눈으로 검증(3개 페이지 타입 x 2테마)
  - 검증 중 CSS 버그 발견: `.links`(획득방법 표 셀의 인라인 링크 목록)가 부모 `<td>`의
    `white-space: pre-wrap`을 상속받아서 링크마다 줄바꿈되던 문제 → `.links`에
    `white-space: normal` 추가로 수정. 지난 세션에 고친 표 셀 가독성 버그와 같은 계열의
    원인(pre-wrap이 의도치 않은 요소까지 적용됨)이라 흥미로운 재발 패턴

## 미해결
- 카테고리 목록 페이지 통계 컬럼 표/정렬/필터 — 별도 세션에서 카테고리별 스키마 판단
  작업 필요
- "이 항목을 참조하는 곳" 백링크 섹션 — 역방향 링크 인덱스 구축 필요
- 나머지 70개 카테고리 전체에 대한 스타일 엣지케이스 확장 검토는 그대로 미해결
