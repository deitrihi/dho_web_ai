# 백링크 섹션 + 카테고리 목록 통계 표 구현

## 요청
- "남은 항목도 진행해줘" — 이전 세션들에서 보류해뒀던 두 항목: "이 항목을 참조하는 곳"
  백링크 섹션, 카테고리 목록 페이지의 통계 컬럼 + 정렬 표

## 백링크 섹션

### 조사
- 원본 사이트의 정확한 백링크 집계 알고리즘은 알 수 없음(캐시 HTML의 압축 JSON 스트림을
  봐도 완전히 역공학하긴 어려움). 대신 우리가 이미 가진 데이터로 명확하게 계산 가능한
  정의를 채택: "다른 항목의 raw_attrs/raw_tables 어딘가에 이 항목으로의 링크가 있으면
  backlink"
- equipment/6582로 검증해보니 스킬 "사교"(skill/2309)가 **자기 자신의 페이지**에 있는
  "장비품" 속성으로 equipment/6582를 링크하고 있어서 backlink로 잡히는 것 확인 — 원본의
  "참조하는 곳" 섹션과 같은 종류의 역방향 관계로 보임(스킬 페이지에 "이 스킬을 주는
  장비품" 같은 속성이 있고, 그 반대 방향을 여기서 보여주는 것)

### 행동
- `build_backlinks.py` 신규: raw_attrs.links_json + raw_tables 셀 링크를 전부 스캔해서
  `item_backlinks(target_category, target_item_id, source_category, source_item_id,
  source_label)` 테이블 생성. 자기 자신을 가리키는 링크는 제외. 566,481건 스캔 →
  중복 제거 후 440,926건 적재
- 분포 확인: 평균 14건, 최댓값 6,468건(흔한 스킬/재료). 카테고리당 30건까지만 노출하고
  나머지는 "OO 외 N건 더"로 표시하는 방식 채택(전체 페이지네이션은 범위 밖으로 보류)
- `dho_webapp.py`의 `get_backlinks()` + `item_detail()` 연결, `templates/item.html`/
  `static/style.css`에 뱃지+목록 섹션 추가
- **버그**: 첫 구현에서 backlink 그룹 dict에 `"items"` 키를 썼더니 Jinja가
  `{% for it in g.items %}`를 dict의 내장 `.items()` 메서드로 해석해버려서
  `TypeError: 'builtin_function_or_method' object is not iterable`로 500 에러남.
  `"entries"`로 키 이름을 바꿔서 해결

## 카테고리 목록 통계 표

### 조사
- 원본 사이트를 직접 봤을 때(지난 세션) 카테고리 목록이 정렬 가능한 다중 컬럼 표라는
  걸 확인했지만, 그때는 70개 카테고리마다 어떤 속성을 컬럼으로 쓸지 수작업 판단이
  필요해 보여서 범위 밖으로 미뤘음
- 이번에 `dho_structured.sqlite3`에 이미 있는 `materialize_generic.py`가 만든
  카테고리별 테이블(`equipment`, `quest` 등)을 재사용할까 검토했지만, cannon/recipe/
  consumable 3개는 손으로 만든 테이블이라 컬럼명이 영어(예: penetration, ball_speed)라
  화면에 그대로 보여주기 부적합하고, tarotCard는 컬럼이 아예 없었음(전용 스크립트가
  attrs 기반 컬럼을 안 만듦) — 카테고리마다 다른 컨벤션이라 그대로 쓰기 어려움
- 대신 `raw_attrs`를 직접 써서(상세 페이지와 동일한 소스) 휴리스틱으로 컬럼을 자동
  선정하기로 결정: 평균 글자 수 ≤20자인 속성만, 문서 순서대로 최대 7개까지. quest의
  "진행"(평균 511자)/"공략"(95자) 같은 장문 속성은 자동으로 제외되고, "분류"/"내구도"/
  "공격력" 같은 짧은 분류값만 남음 — cannon/equipment로 미리 검증해보니 원본과 상당히
  비슷한 컬럼 구성이 나옴

### 행동
- `dho_webapp.py`의 `get_list_columns()`: 카테고리별 라벨 평균 글자수 계산, 숫자
  전용 컬럼인지도 판별(정렬 시 텍스트 정렬 대신 `CAST(...AS INTEGER)` 쓰기 위함)
- `category_list()` 재작성: `raw_attrs`를 `MAX(CASE WHEN label=? THEN text END)`로
  피벗해서 이름+컬럼값 표 데이터 생성. `sort`/`dir` 쿼리 파라미터로 정렬(파라미터는
  실제 컬럼 라벨 화이트리스트와 대조 후에만 raw SQL 문자열에 꽂아넣음 — SQL 인젝션
  방지). 속성이 없는 카테고리는 기존 단순 이름 목록으로 자동 폴백
- `templates/category.html`: 정렬 가능한 헤더(클릭 시 ▲▼ 토글) + 표 렌더링 추가
- **버그**: 처음엔 `ORDER BY {정렬컬럼}, ic.item_id ASC`에서 기본 정렬값 "item_id"를
  안 붙인 채로 그냥 썼더니 `items_core`와 `raw_attrs` 둘 다 item_id 컬럼이 있는
  JOIN이라 `sqlite3.OperationalError: ambiguous column name: item_id`로 500 에러남.
  "item_id"/"name" 정렬일 때는 `ic.item_id`/`ic.name`으로 명시적으로 qualify하도록 수정
